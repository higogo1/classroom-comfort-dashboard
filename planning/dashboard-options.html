안 A · 회로 P01

책상 환경·조명 도우미

이미 조립해 둔 P01을 그대로 씁니다. 대시보드는 state 메시지의 light_raw · pot_raw · button_pressed · temperature_c · humidity를 보여 주고, LED / AUTO / THRESH / STOP 명령을 보냅니다.

대시보드 화면 구성

  • 첫 줄 요약: “밝기 낮음 · 자동 조명 켜짐 · 26.1°C / 48%”
  • 센서 카드 4개 + 최근 10분 추세선
  • 조명 제어: 켜기 · 끄기 · 자동, 기준값 2개(켜는 값 < 끄는 값)
  • 연결 상태: 마지막 수신 3초 넘으면 경고
안 B · 새 회로 PL1 (제안)

화분 돌봄 스테이션

K07 수위, K05 조도, K09 DHT11, K11 RGB, K12 부저 단품 배선을 한 빵판에 합친 제안입니다. RGB(D5·D6·D9)는 PWM이 필요하고, 부저 tone()은 Timer2라 D3·D11 PWM에만 영향을 줘서 서로 겹치지 않습니다.

수위 센서는 흙 수분 센서가 아닙니다. 화분 옆 급수 물통에 꽂아 “마름 · 조금 · 충분” 세 단계로 보정해 쓰세요. 금속 무늬만 물에 닿게 하고, 보드·USB는 물에서 떨어뜨립니다. 측정할 때만 전원을 켜면 부식이 줄어듭니다.

대시보드 화면 구성

  • 물통 잔량 3단계 표시와 보정 버튼(마른 상태/담근 상태 저장)
  • 오늘 일조 시간 누적(밝기 기준값 이상인 시간)
  • 상태 색: 초록 정상 · 노랑 확인 필요 · 빨강 물 부족 — 색과 함께 글자로도 표시
  • 부저 알림 켜기/끄기, 조용한 시간대 설정
안 C · 새 회로 PL2 (제안)

교실 쾌적도 신호등

K08 소리, K09 DHT11, P03의 세 LED 핀(D10·D11·D12), K15 LCD를 합친 제안입니다. 모듈 세 개는 모두 F–J 쪽에 두고, A–E 쪽에는 LED와 저항만 둡니다.

소리 값은 dB가 아닙니다. 0–1023 상대값이므로 “평소 대비” 기준으로 보여 줍니다. 짧은 소리를 놓치지 않으려면 50ms 구간의 최대–최소 차이를 보내도록 펌웨어를 바꿉니다.

대시보드 화면 구성

  • 불쾌지수 DI = 0.81T + 0.01H(0.99T − 14.3) + 46.3
  • 소음 상대값 막대와 “평소 대비 +40%” 문구
  • 신호등 상태 원격 지정(SIGNAL 0–3) + 자동 판정 모드
  • LCD 안내 문구 보내기(영문 16자 × 2줄, 새 명령 정의 필요)
안 D · P01 + C270 웹캠

비전 × 환경 공간 모니터

빵판은 안 A(P01)와 같습니다. 웹캠은 PC에 따로 꽂고, 10/22에 만든 YOLO 추적·구역 진입 코드가 사람 수와 이벤트만 PC 연결 프로그램으로 넘깁니다. 대시보드는 두 데이터를 한 시간축에 겹쳐 보여 줍니다.

C270 웹캠USB → PCYOLO person 검출 · 추적 ID · 구역 진입
UNO · P01USB 115200 JSON밝기 · 온습도 · 버튼 · LED 상태
PC 연결 프로그램Python · FastAPI두 입력을 합쳐 규칙 판단, 웹소켓으로 전달
웹 대시보드브라우저인원 수 + 환경 추세 + 자동 규칙 기록
개인정보. 영상 프레임은 저장하거나 웹으로 보내지 않고 숫자(인원 수, 진입 횟수)만 넘기는 것을 기본으로 제안합니다. 화면에 “카메라 사용 중” 상태를 항상 표시합니다.

시스템 구조 (공통)

1. UNO 펌웨어1초마다 state 전송, 명령엔 ack/error 응답
2. PC 연결 프로그램COM 포트를 혼자 열고, 웹에 API·웹소켓 제공
3. 웹 대시보드“전송 중 → 보드 적용(ack) → 오류”를 구분해 표시

대안: Chrome의 Web Serial API로 브라우저가 직접 포트를 엽니다. 설치는 간단하지만 Chrome·Edge에서만 되고, 탭 하나만 보드와 연결할 수 있습니다.

ISO 9241 · WCAG 2.2를 이 대시보드에 적용하면

규격 조항을 이 프로젝트의 실제 화면 규칙으로 바꿨습니다. 강의 자료의 “null, 0, 연결 끊김을 섞지 않는다” 규칙도 여기에 들어갑니다.

근거이 대시보드의 규칙
ISO 9241-11사용자·목표·사용 환경을 먼저 정합니다(아래 질문). 효과성(정확한 상태 판단), 효율성(첫 화면에서 3초 안에 판단), 만족도를 측정 항목으로 둡니다.
9241-110 과업 적합성첫 줄에 지금 상태를 한 문장으로 요약하고, 원시값은 그 아래에 둡니다.
9241-110 자기 기술성모든 숫자에 단위와 범위를 붙입니다(light_raw 0–1023 상대값). null은 “측정 대기”, 연결 끊김은 “마지막 값 · 12초 전”으로 0과 구분합니다.
9241-110 기대 일치명령 결과를 네 단계로 보여 줍니다: 전송 중 · 보드 적용(ack) · 오류 · 실물 확인은 사용자 몫. ack를 “LED 켜짐 확인”으로 표시하지 않습니다.
9241-110 오류 허용기준값은 켜는 값 < 끄는 값을 입력 단계에서 검사하고, 정지(STOP) 버튼은 항상 같은 자리에 둡니다. 재연결 때 예전 명령을 자동으로 다시 보내지 않습니다.
9241-110 제어 가능성실시간 갱신을 일시정지할 수 있습니다(WCAG 2.2.2와 같은 요구).
9241-110 개인화라이트/다크, 갱신 주기, 경고 소리를 사용자가 고릅니다.
WCAG 1.4.1 · 1.4.11상태는 색만으로 구분하지 않고 글자와 모양을 함께 씁니다. 그래프 선·경계는 대비 3:1 이상, 글자는 4.5:1 이상.
WCAG 2.1.1 · 2.4.7모든 제어를 키보드로 쓸 수 있고 초점 표시가 보입니다.
WCAG 2.4.11 2.2 신규고정 헤더가 초점 받은 요소를 가리지 않게 scroll-padding-top을 둡니다.
WCAG 2.5.7 2.2 신규기준값 슬라이더 옆에 숫자 입력과 ± 버튼을 둬서 끌지 않고도 바꿀 수 있게 합니다.
WCAG 2.5.8 2.2 신규모든 버튼·토글은 최소 24×24 CSS px.
WCAG 3.2.6 2.2 신규도움말(배선·명령 설명) 링크를 모든 화면의 같은 위치에 둡니다.
WCAG 3.3.7 · 3.3.8 2.2 신규COM 포트·보정값은 한 번 입력하면 기억합니다. 로그인이 생기면 퍼즐형 인증을 쓰지 않습니다.
WCAG 4.1.3경고가 새로 생길 때만 aria-live="polite"로 알립니다. 1초마다 바뀌는 숫자는 읽어 주지 않습니다.
